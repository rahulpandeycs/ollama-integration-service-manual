# Player Service Model

This directory contains the Python similarity-recommendation service used by the Java player application.

The model is an unsupervised `NearestNeighbors` recommender. It finds players similar to a seed player or hypothetical profile using birth date, height, weight, batting hand, and throwing hand. It does not predict player performance or optimize a baseball lineup.

## Train and evaluate

Install the Python dependencies with Poetry, then run the reproducible training workflow from this directory:

```shell
poetry install
poetry run python -m a4a_model.train \
  --input a4a_model/player.csv \
  --model-output a4a_model/team_model.joblib \
  --features-output a4a_model/features_db.csv \
  --metrics-output a4a_model/model_metrics.json
```

The workflow:

- Uses the same fitted preprocessing for training and inference.
- Searches a bounded set of distance metrics and neighbor counts automatically.
- Saves the selected model, enriched feature data, and versioned metadata.
- Produces unlabeled retrieval diagnostics. These are proxy metrics, not precision or recall against a ground-truth team dataset.

To train only the baseline configuration:

```shell
poetry run python -m a4a_model.train --no-automl
```

Compare a current player dataset with the training reference and write a drift report:

```shell
poetry run python -m a4a_model.monitor \
  --reference a4a_model/player.csv \
  --current a4a_model/player.csv \
  --output a4a_model/drift_report.json
```

The report contains feature-level population stability index (PSI), missing-rate changes, and `stable`, `watch`, or `drift` statuses. Use a reviewed or historical team dataset separately for recommendation-quality metrics.

## Run the service

Run locally from the `player-service-model` directory:

```shell
MODEL_FAILURE_SIMULATION=false poetry run python -m a4a_model.server
```

The service listens on port `5000`. It can also be built and run with Docker:

```shell
docker build -t a4a-model .
docker run --rm -p 5000:5000 -e MODEL_FAILURE_SIMULATION=false a4a-model
```

The service loads paths relative to `a4a_model`, so it can be started from any working directory. `MODEL_PATH`, `FEATURES_PATH`, `MODEL_VERSION`, and `FEEDBACK_LOG_PATH` can override the defaults.

## Generate a team

```shell
curl -H "Content-Type: application/json" \
  -d '{"seed_id":"aaronha01","team_size":5}' \
  http://127.0.0.1:5000/team/generate
```

The response contains the recommendation ID and model version used for the request:

```json
{
  "seed_id": "aaronha01",
  "prediction_id": "38f5f02f-b1be-4282-8d0e-865b3995d50a",
  "model_version": "similarity-...",
  "team_size": 5,
  "member_ids": ["aaronha01", "combspa01", "maurero01", "cummijo01", "flemida01"]
}
```

The request may instead contain a hypothetical profile:

```json
{
  "features": {
    "birth_year": 1934,
    "height": 72,
    "weight": 180,
    "bats": "R",
    "throws": "R"
  },
  "team_size": 5
}
```

`team_size` must be between 1 and 25, and the request must contain either `seed_id` or `features`.

## Feedback and monitoring

Feedback must reference a prediction generated by the current process:

```shell
curl -H "Content-Type: application/json" \
  -d '{"seed_id":"aaronha01","member_id":"maurero01","feedback":-1,"prediction_id":"38f5f02f-b1be-4282-8d0e-865b3995d50a"}' \
  http://127.0.0.1:5000/team/feedback
```

Negative feedback excludes that member from later recommendations for the seed. Exclusions and prediction records are process-local; set `FEEDBACK_LOG_PATH` to append JSON events for offline analysis.

Runtime metrics are available at:

```shell
curl http://127.0.0.1:5000/metrics
curl http://127.0.0.1:5000/health
```

Metrics include request outcomes, timeouts, latency, unknown seeds, feedback outcomes, and the active model version. Generation and feedback events are also emitted as JSON log lines.
